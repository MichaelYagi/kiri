Batch cropping

KiriBatch steps one shared Kiri instance through a queue of images.

One DOM/stage instance is reused across images — not one instance per image — so every interaction you already know (drag, zoom, rotate, flip, filters) works exactly the same, with no separate API to learn.

import { KiriBatch } from "@michaelyagi/kiri";

const batch = new KiriBatch(container, options, [
  { source: fileA },
  { source: fileB },
]);

while (await batch.next()) {
  // batch.cropper now shows batch.current().source — let the user adjust it
  // (drag/zoom/rotate/whatever), then capture it:
  await batch.capture();
}

batch.results(); // all crops, in order
batch.destroy();

Adding items later

You don't have to pass the whole queue up front — add() appends to it:

const batch = new KiriBatch(container, options);
fileInput.addEventListener("change", () => {
  for (const file of fileInput.files) batch.add({ source: file });
});

A typical UI loop

nextButton.addEventListener("click", async () => {
  const hasNext = await batch.next();
  if (!hasNext) {
    showResults(batch.results());
    return;
  }
  statusEl.textContent = `Editing item ${batch.current().source.name}`;
});

prevButton.addEventListener("click", () => batch.previous());
captureButton.addEventListener("click", () => batch.capture());

previous() is the mirror image of next() — it steps cropper back one item and returns false (without moving) once you're already on the first item, so a "Back" button can disable itself the same way a "Next" button does at the end of the queue.
